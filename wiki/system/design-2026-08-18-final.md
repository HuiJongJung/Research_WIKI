# 확정 설계 2026-08-18 (구현 검토 반영판)

> 이 문서가 confidence map · regularization · densification · prior 네 요소의 **현행 확정 설계**다. 이전 설계 서술과 충돌하면 이 문서가 우선한다. 수치의 진실 원천은 여전히 EXPERIMENT.md.

## 0. 구현 검토 결과 요약 (2026-08-18, 서브에이전트 2건)

### 무사한 것

**생성 격자와 조회 좌표계가 정확히 일치한다.** 복셀 중심이 `grid_sample` 인덱스에 정수로 떨어지며, `/2.0` + `align_corners=False` 조합이 맞다(`align_corners=True`였으면 반 칸 어긋났다). 축 순서(x-major 저장 → grid에 z,y,x 반전)도 올바르다. `ray_confidence`와 `pixels_to_world`는 같은 식의 전개이며 카메라 규약이 MILo 자체 코드와 문자 그대로 동일하다. **좌표계 원인으로 과거 결과가 무효화되지는 않는다.**

점/광선 채널의 voxel 인덱싱 일관성, contraction 역함수, COLMAP 카메라 변환, `kappa = n − λ_max(M)` 수식과 엣지케이스도 확인됨.

### 반드시 고쳐야 하는 것

1. **최대 쌍각 3회 순회 근사가 느슨한 하한이다.** 반례 실측: 궤도형 배치(평면 양 끝 두 대 + 축을 벗어난 한 대)에서 **80.15° 대 실제 120.00°**. 평균에서 가장 먼 방향이 진짜 극단 쌍의 구성원이 아니면 빗나간다. **편향 방향이 우리에게 유리한 쪽**(과소평가 → narrow 과다 판정 → DEGEN·divergence 부풀림)이라 특히 위험하다.
2. **점유 판정이 없어 TEXTURELESS·divergence가 빈 공간으로 채워진다.** 격자 대부분이 공기이므로 "divergence 집합이 비어있지 않다"가 거의 자동으로 참이 되어 검정력이 없다. H2는 GT와 mesh가 둘 다 있는 voxel만 채점하므로 영향받지 않는다.
3. **FOV 카메라 모델 intrinsics 오배정** (`field_v1.py:98-100`): `fx, fx, fy, cx`를 반환. 우리 씬이 이 모델을 쓰는지 확인 필요.
4. **txt `images.txt` 홀짝 페어링** (`:124-125`): 등록 특징점 0개인 이미지가 하나라도 있으면 이후 전부 어긋남. `.bin` 경로는 안전.
5. **`kappa_lo` 분위수 동률 붕괴** (`:457,462`): `kappa_geo`가 0에 뭉치면 분위수가 0이 되어 `narrow_k`가 공집합. 게이트 A의 "집합 크기 일치" 공정성 전제가 무너질 수 있었다.
6. **lever5 깊이 미정제** (`train_field.py:373,378`): 빈 픽셀 inf/0이 평균 정규화 분모를 오염. lever3은 처리하는데 lever5만 누락.
7. **"예산 중립"이 근사였다**: 가중 평균을 전체 H·W로 내는데 loss는 `rasterization_mask` 안에서만 걸린다. 실효 총량이 `sum(mask·w)`라 마스크와 가중이 상관되면 어긋난다. **E4-reg의 A1 대 A0 판정은 예산과 무관하므로 유효하나, "같은 총량" 서술은 정정해야 한다.**

### 서술 정정

- `pot_angle`은 최대 쌍각의 **느슨한 하한**. `tri_angle`도 track에서 6대만 뽑는 하한(같은 방향 편향)
- kappa 주석의 "catastrophic cancellation 회피" 근거는 성립하지 않음(정규화해도 오차 동일, float64에서 애초에 무해)
- `q_geo = 0.5가 등방`은 틀림. 3D 등방은 2/3, 0.5는 **평면 등방**(궤도 촬영)
- **`field_lookup.py`가 v1 npz의 `kappa_geo`·`state_kappa`를 로드조차 하지 않는다.** 지금까지 실험을 "v1 필드로 했다"고 쓰면 안 된다
- `lever3_mode=global`은 수치적으로 `off`와 동일(둘 다 전체 평균). 정보량 0인 arm
- `clone_thr_scale`은 호출처 0건인 죽은 코드이며 docstring이 실제 배선(이진 게이트)과 반대를 주장

## 1. Confidence map — 관측 발자국의 강건 폭

> **08-18 재개정 (13:55판 대체).** 이전 판의 `a_perp`/`W_minor` 설계는 **반증되어 폐기**한다. 아래가 유일한 확정 정의다. 13:55판을 읽고 구현에 착수한 경우 해당 채널을 제거할 것.

### 1-0. 정의

```
1. 시선 방향들을 평균 방향 기준 접평면에 투영 → 2D 점 뭉치
2. 제1주축(가장 퍼진 방향)을 구함
3. 그 축 위 좌표의 p10 ~ p90 폭을 각도로 환산      → spread
4. conf = clip( spread / 30°, 0, 1 )
```

**단일 값이며 전체 카메라가 분위수 계산에 들어간다.**

### 1-0-1. `a_perp`(면외 퍼짐) 폐기 — 반증 기록

이전 판은 "카메라가 수평 호로만 돌면 수직 시차가 0이라 표면이 위아래로 자유롭게 기운다"를 근거로 면외 퍼짐 `W_minor`를 confidence로 삼았다. **이 근거는 수치 계산으로 반증됐다.**

| 조건 | λ_min (가장 제약이 약한 방향의 정보량) | 약한 축 | W_minor |
| --- | --- | --- | --- |
| 수평 120° / 수직 0° | 6.338 | **시선 방향(깊이)** | 0° |
| 수평 120° / 수직 5° | 6.346 | **시선 방향(깊이)** | 7.4° |

**면외 퍼짐을 0에서 5도로 늘려도 정보량이 0.1%밖에 변하지 않으며, 약한 축은 전 조건에서 항상 깊이 방향이다.** 카메라가 모두 한 평면에 있어도 점의 면외 위치는 삼각측량으로 결정된다. 면외 퍼짐에 대응하는 영방향(null direction)은 존재하지 않는다.

**실측 분포도 같은 결론을 지지한다** (Ignatius, 실험 세션 산출): `W_major` 중앙값 60.1°인데 `spread_min`(=W_minor) 중앙값은 **8.4°**다. 표면 절반 이상이 30도 아래로 떨어져 위험 표시가 거의 전면에 깔리며, 판별력이 없다.

### 1-0-2. 최댓값 대신 분위수 폭을 쓰는 이유

최대 쌍각은 **카메라 한 대에 의해 결정**되므로 오등록·오매칭 한 대가 값을 뒤집는다. 합성 검증 결과:

| 조건 | 최대 쌍각 | 투영 p10–90 |
| --- | --- | --- |
| 좁은 호 8° (30대) | 8.1° | 7.0° |
| 좁은 호 8° + 이상치 1대 | **64.0°** | **7.2°** |
| 좁은 호 8° + 이상치 3대 | **64.0°** | **7.7°** |
| 양끝 두 무리 (15대씩, 진짜 광각) | 74.7° | **72.1°** |

**이상치 1대가 최댓값을 8배로 뒤집는데 분위수 폭은 흔들리지 않으며, 절반이 지지하는 진짜 광각은 그대로 높게 잡는다.**

가림 한계와도 정합한다 — 우리 가시 판정은 프러스텀 기반이라 상한이고, **멀리서 넓은 각으로 보는 카메라 한 대는 실제로는 가려져 있을 확률이 가장 높은 카메라**다. 그런 한 대가 voxel을 안전으로 뒤집는 것을 막는 것이 옳다.

**쌍각 분위수는 쓰지 않는다.** 이상치 1대가 나머지 전부와 쌍을 만들어 큰 값 쌍이 n−1개 생기므로 쌍 단위 분위수는 증폭된다(실측: 쌍각 p95가 7.0 → 57.4로 붕괴). **반드시 카메라 단위로 분위수를 잡는다.**

**trim 수준 p10–90의 근거**: 어떤 baseline이든 관측 카메라의 10% 이상이 양쪽에서 지지해야 인정한다는 뜻이다. p5–95는 이상치 3대(9%)에서 무너졌으므로(63.8) p10–90이 안전 마진을 갖는다.

### 1-0-3. 관측 횟수를 넣지 않는 이유

핵심 명제가 "관측 횟수 ≠ 관측 품질"이므로 횟수를 넣으면 자기 부정이 된다. 실측도 같다 — κ는 게이트 A에서 각도 단독에 졌고 `n_views`는 C6에서 최약이었다.

**패배 이유**: κ는 잡음 제한 모델이라 15대가 10도에 몰려도 √15의 이득을 준다. 본 레짐은 **모호성 제한**이므로 평행한 시선을 아무리 모아도 구별되지 않는 것은 구별되지 않는다. 실측 확인: 같은 형상에서 대수를 30 → 120으로 늘리면 λ_min이 0.069 → 0.271로 4배 튀지만 각도 기반 측도는 전부 불변이다.

### 1-0-4. 정규화 30도 절대 기준

깊이 불확실도가 대략 `1/sin(각)`이며 30도가 급격히 나빠지는 무릎이다. 덱 슬라이드 18의 "관측 각 0° → 30°(두 씬 공통)" 컬러바와 "두 씬이 같은 눈금을 공유한다"는 주장이 이 절대 기준에 의존하므로 유지한다.

**렌더 정정**: 현행 덱의 map 이미지는 `ang_max=90`으로 렌더된 것이다. **30으로 다시 뽑아야 한다.**

**발화율 예측**: `W_major` 중앙값이 60.1°이므로 30도 기준에서 표면의 상당 부분이 conf=1로 포화한다. 분위수 폭은 최댓값보다 다소 작으므로 발화율이 그보다 높을 것이나, 폐기된 `spread_min`(중앙값 8.4°)처럼 전면이 붉어지지는 않을 것으로 예상한다. **실측 분포를 먼저 보고한 뒤 조정 여부를 판단한다.**

### 1-1. 계산 절차

```
# 접평면 투영
m  = normalize(sum(dirs))
e1 = normalize(dirs 중 m과 가장 덜 나란한 축과의 외적)     # 수치 안정성 주의
e2 = cross(m, e1)
t  = stack([dirs @ e1, dirs @ e2], -1)                     # (n, 2)
t  = t - t.mean(0)

# 제1주축
_, _, Vt = svd(t)
proj = t @ Vt[0]                                            # (n,)

# 분위수 폭 (라디안 → 도)
spread = degrees( arcsin(quantile(proj, 0.90)) - arcsin(quantile(proj, 0.10)) )
```

카메라 순회 1회로 방향을 모으고, voxel마다 위 계산. **최대 쌍각(`W_major`)은 진단·보고용으로 함께 저장**하되 conf 정의에는 들어가지 않는다. k-극단 집합은 `W_major`를 정확히 구할 때만 쓴다.

### 1-3. 점유 조건화

격자 대부분이 공기인데 `TEXTURELESS = 각 넓음 & 점 없음`이라 빈 공간이 통째로 들어가고 "divergence가 비어있지 않다"가 거의 자동으로 참이 된다. `occupied = (n_pts > 0)`를 26-이웃 1회 팽창하고, `TEXTURELESS`·`divergence`를 조건화 전후 둘 다 보고한다.

### 1-6. 버그 수정

FOV intrinsics(해당 씬일 때), txt 파싱(또는 `.bin` 강제), `kappa_lo`를 순위 기반으로, `disp`를 `n_views<2`에서 0 마스킹.

## 2. Regularization — 자유도 축소

confidence가 낮은 곳에서 **MILo 자체의 mesh–Gaussian 일관성 항**을 더 강하게 걸어 자유도를 낮춘다. 외부 모델이 개입하지 않는다.

| 항목 | 값 |
| --- | --- |
| 형태 | 가산형 `w = 1 + λ(1−conf)`, 하한 1 (뺏지 않음) |
| 강도 λ | 2.0 |
| 적용 | mesh 깊이·법선 두 항에 픽셀별 |
| 조회 | **광선 최솟값(`ray_min`)으로 교체** |

**수정 사항**: 깊이 `nan_to_num` 추가, `ray_confidence` 내부에 유효하지 않은 깊이 마스크 내장.

**배선 전 진단 필수**: `ray_min`이 카메라~표면 사이 자유공간에 지배되지 않는지 확인. `at_surface`와 `ray_min`의 분포를 비교한다(`diag_lookup.py`가 이미 둘 다 산출).

## 3. Densification — 연속 clone 억제

```
평소:  grads > τ₀                        → clone
우리:  grads > τ₀ · (1 + s·(1 − conf))    → clone
```

| 항목 | 값 |
| --- | --- |
| 기준값 | conf (1-4 승자 형태) |
| 억제 강도 s | 1.0 (임계 최대 2배) |
| 발동 범위 | **전 영역** (현행 d/R<0.5 제한 해제) |
| split | 미개입 |
| depth_reinit 필터 | 미개입 (이번 런) |

**사유**: 현행은 근거리 floater용 설계였고 우리 표적과 실제 악화 지점은 원거리 외벽이다. 연속으로 가면 voxel 경계 뒤집힘이 사라지고, conf 기반이라 4상태 라벨의 "각 좁음 OR 점 부족" 혼합 문제도 회피한다.

**위험 인지**: 원거리는 Gaussian이 원래 부족해 clone을 조이면 결손이 늘 수 있다. split을 열어두는 것이 대비이며, **"뭉갬"이 "구멍"으로 바뀌는 것도 결과로 보고**한다.

**구현**: `clone_thr_scale`이 죽은 코드이므로 배선 필요. `densify_and_clone`이 스칼라 임계를 쓰므로 점별 벡터 비교로 수정.

## 4. Prior — 배치 규칙 자체를 시험 대상으로

### 4-1. 경위

prior 주입(lever3)은 구현됐으나 **표적 주입 런이 실행된 적이 없다.** D1은 균일 주입 런을 사후에 각도 사분위로 분해한 분석이었고, "표적하면 피해를 집중시킨다"는 측정이 아니라 **추론**이었다. 그 추론으로 실행 취소를 권고한 것이 위키 세션이며, 결과적으로 **핵심 주장("어디에 넣는지가 중요하다")이 직접 시험되지 않았다.**

### 4-2. MILo의 prior 경로 실체

- 모델: Depth Anything V2, 학습 전 1회 전 이미지 추론
- loss: **깊이 순서(order) loss.** 픽셀마다 근처(이미지 5% 이내) 픽셀 하나를 무작위로 골라 깊이 대소를 비교하고, **prior의 크기를 버리고 부호만** 쓴다. 순서가 맞으면 loss 0
- 따라서 **절대 깊이 정확도(AbsRel)는 이 loss에 들어가지 않는다.** 발표 논거를 절대 오차에서 옮겨야 한다

### 4-3. 설계

**같은 총량을 세 가지로 배치해 비교한다.**

| arm | 배치 | 구현 |
| --- | --- | --- |
| P-low | conf 낮은 곳에 더 (원래 가설) | `lever3_mode selective` — 있음 |
| P-high | conf 높은 곳에 더 (D1 방향) | `w = 1 + λ·conf` — 한 줄 추가 |
| P-uniform | 균일 | **`--depth_order` 단독** (lever3 global은 off와 수치 동일) |

- 가중은 **rasterization mask 안에서** 평균 1로 정규화 (검토에서 드러난 예산 근사 문제 수정)
- `--lever3_state_mask none` (기본 `obs_degen`이 4상태 라벨로 제한하므로 해제)
- 조회는 정규화 arm과 통일 (`ray_min`). 세 arm이 같은 조회를 쓰므로 배치 비교는 어느 쪽이든 유효
- 모델은 V2로 먼저(D1과 같은 세대라 직접 대조 가능), 배치가 유의하면 DA3로 재확인

**발화율 보고 주의**: 순서가 이미 맞는 픽셀은 loss가 0이므로, 가중 분포만이 아니라 **loss가 살아 있는 픽셀 비율**을 함께 보고해야 실제 발화율이 된다.

### 4-4. 사전 등록 판독

셋이 노이즈 바닥을 넘어 갈리면 **"배치가 중요하다"가 어느 쪽이 이기든 성립한다.** P-high가 이기면 원래 주장은 참이고 우리가 올바른 규칙을 발견한 것이 된다. 셋이 비슷하면 배치 무관으로 정규화 계열로 회귀한다. **이 해석을 결과 보기 전에 고정한다.**

## 7. 구현 사양 확정 (2026-08-18, 재료 실사 후 추가)

이전 서술이 모호해 구현자가 설계를 겸하게 되는 지점이 있었다. 아래로 고정한다.

### 7-1. `a_max` — k-극단 집합 의사코드

```
입력: dirs (n,3) 단위벡터 (voxel → 각 가시 카메라 방향), k = 8
출력: a_max (도), pair (p,q)

S = []                                     # 극단 집합 인덱스
mean = normalize(sum(dirs))
S.append( argmin_i <dirs[i], mean> )       # 평균에서 가장 먼 것 하나로 시작
for t in 1 .. k-1:
    j = argmax_i ( min_{s in S} <dirs[i], dirs[s]> 의 음수 )
      = argmax_i ( max_{s in S} angle(dirs[i], dirs[s]) )   # 이미 뽑힌 것들에서 가장 먼 것
    S.append(j)                            # 중복은 건너뜀
(p,q) = argmax_{a,b in S, a<b} angle(dirs[a], dirs[b])      # 전수 쌍 (k=8이면 28)
a_max = angle(dirs[p], dirs[q])
```

카메라 순회 k회. k = 4 / 8 / 16을 모두 시도해 수렴을 확인하고 표로 보고한다.

### 7-2. `a_perp` — 정의 확정 (하나만)

```
n_hat = normalize( cross(dirs[p], dirs[q]) )    # 최대 쌍이 이루는 평면의 법선
out_i = arcsin( clip(<dirs[i], n_hat>, -1, 1) ) # 각 방향의 면외 각 (부호 있음)
a_perp = max_i(out_i) - min_i(out_i)            # 면외 총 퍼짐 (도)
```

**대체 정의를 쓰지 않는다.** 이 정의를 택한 이유: 카메라가 완전한 수평 호로만 돌면 모든 방향이 한 평면에 있어 `<dirs[i], n_hat> = 0`, 따라서 **`a_perp = 0`으로 정확히 표적 실패 모드를 짚는다.** 전 구면 촬영이면 크다.

전체 n개 방향에 대해 계산한다(k-극단 집합만이 아님). 순회 1회 추가.

### 7-3. 점유 마스크

```
occupied = (n_pts > 0)
occupied = occupied | dilate_26neighbor(occupied)   # 1회
```

`TEXTURELESS`·`divergence` 카운트를 **조건화 전후 둘 다** 보고한다.

### 7-5. prior 가중 스케줄 (해석 시 필수 인지)

`field.yaml`의 prior 가중은 **학습 중 감쇠**한다: iter 600에 1.0 → 1500에 0.1 → 3000에 0.01 → 8000에 0.001 → 13000에 0.0001. 즉 **prior는 초반에만 강하게 작용**한다. 배치 실험(P-low/high/uniform) 결과를 읽을 때 "초반 형상 형성기의 배치 효과"로 해석해야 하며, 학습 후반의 효과가 아니다. 세 arm이 같은 스케줄을 쓰므로 배치 비교 자체는 유효하다.
