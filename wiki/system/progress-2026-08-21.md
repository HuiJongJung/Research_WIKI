# 진행 2026-08-21

## 3축 규율 문서 신설 — 흩어진 규칙을 한곳으로

### 왜 바꿨나

규율(한 번 배우면 계속 적용되는 규칙)이 세 군데에 흩어져 있었고, 두 곳은 문제가 있었다.

1. **연구 방법 규율이 `research-status.md` §7-1에 얹혀 있었다.** status는 **덮어쓰는** 문서, 규율은 **쌓는** 문서라 수명이 다르다. status를 크게 갈아엎을 때 규율이 함께 휩쓸릴 구조였다.
2. **발표 규율 2종이 `논문 발표/` 폴더에 있었고 그 폴더는 git 추적이 되지 않는다.** 쌓는 문서를 복구 불가능한 곳에 두고 있었다.

### 무엇을 했나

`wiki/system/`에 `rules-` 접두어로 3개를 나란히 세웠다. 위키는 페이지 종류가 코드에 고정이라 새 하위 폴더를 만들면 인덱스에서 빠지므로, 폴더 대신 파일명 접두어로 묶었다.

| 파일 | 축 | 출처 | 용도 |
| --- | --- | --- | --- |
| `rules-research.md` | 연구 방법 | `research-status.md` §7-1 이관 | 방향 논의 세션이 논의 시 준수 + 사용자 연구 참조 |
| `rules-deck.md` | 발표 자료 구성 | `논문 발표/PPT_초안_규칙.md` 이관 + 보고서 구조 규율 발췌 편입(§2-1) | 스킬 실행 규칙 + 사용자 자료 검토 |
| `rules-talk.md` | 발표 방법 | `논문 발표/발표_팁.md` 이관 | **사용자가 발표 전 직접 열람.** 세션은 쌓기만 함 |

`research-status.md` §7-1은 포인터 한 문단으로 축소했고, §0 참조표에 3줄을 넣었다.

### 스킬 경로 정리

`seminar-deck-draft` 스킬은 `references/rules.md`를 정본으로 읽는다(스킬이 위키를 못 찾는 상황에서도 살아야 하므로 사본 유지). `PPT_초안_규칙.md`를 가리키던 4곳(SKILL.md ×2, build-recipe.md, 헬퍼 py ×2)을 새 경로로 고쳤다. 동기화는 frontmatter를 벗겨 복사하는 awk 한 줄이며 `CLAUDE.md`에 의무로 명시했다.

## 보완 — 연구 방법 규율이 세 군데에 흩어져 있었다

첫 이관에서 `research-status.md` §7-1만 옮겨 `rules-research.md`가 5줄짜리로 남았다. 사용자가 "전에 정리한 게 어디 갔느냐"고 지적해 전수 확인한 결과, 연구 방법 규율은 실제로 세 군데에 있었다.

| 있던 곳 | 내용 | 처리 |
| --- | --- | --- |
| `Desktop/0818 연구방향 피드백.md` 2부 | **방법 원칙 8개** (08-19 확정분) | → `rules-research.md` §1로 승격. 원본에는 승격 표시만 남김 |
| `research-status.md` §7 꼬리 | 평가 실행 규약 4개 | → §3으로 이관, 원위치는 포인터 |
| `research-status.md` §7-1 | 가설·기여 5개 | → §2 |
| (신규) | 스코프 규율 — 최대 쌍각 표기, 건전성 비대칭, 절대값 비교 금지, 예비 결과 단서, 귀무 대조 의무 | → §1-1로 명문화. 그동안 대화로만 지켜지던 것 |

`feedback-*.md` 4개는 **동결 원본이므로 건드리지 않았다.** 규율은 거기서 뽑아낸 결과물이고 원본은 "무슨 지적을 받았는가"의 기록으로 남는다.

**남은 불일치**: `research-status.md` §8 용어 규칙도 성격상 규율 문서에 와야 하나, `CLAUDE.md`와 `SURVEY_BRIEF.md`가 "§8을 따른다"로 참조 중이라 이관 시 3개 문서를 함께 고쳐야 한다. `rules-research.md` §4에 판단 대기로 표시했다.

## 규율과 방향의 분리 — direction 일지 신설, progress 형식 종료

`rules-research.md`에 두 종류가 섞여 있다는 지적을 받았다. **원론적 연구 방법**과 **내 연구의 현재 방향**은 수명이 다르다. 표적이 바뀌면 후자는 통째로 바뀌지만 전자는 남는다.

- `rules-research.md`를 **원론만** 남기고 재작성했다 (§1 가설과 증명 / §2 기여와 선행 / §3 상수와 임계 / §4 실험 설계 / §5 비교와 보고 / §6 제목과 서술).
- 연구 특정 결정(방법 원칙 5·6·8·9·A6, 최대 쌍각 표기, 건전성 비대칭, hole 클로즈업 규약, field 시각화)은 **`direction-2026-08-17.md` §3**으로 옮겼다.
- **주간 방향 일지 `direction-YYYY-MM-DD.md` 신설.** 파일명은 그 주 월요일, 큰 전환이 있으면 그날 날짜로 새 파일. 사용자가 자기 연구의 궤적을 돌아보기 위한 문서다.
- **`progress-YYYY-MM-DD.md` 형식은 이 파일로 종료.** 두 이력을 병행하면 반드시 어긋나므로 direction이 흡수한다. 기존 8개 파일은 그대로 남긴다.

가르는 기준: **표적이 바뀌어도 살아남으면 `rules-research.md`, 함께 바뀌면 `direction-*.md`.**
