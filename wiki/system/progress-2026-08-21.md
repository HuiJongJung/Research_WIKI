# 진행 2026-08-21

## 3축 규율 문서 신설 — 흩어진 규칙을 한곳으로

### 왜 바꿨나

규율(한 번 배우면 계속 적용되는 규칙)이 세 군데에 흩어져 있었고, 두 곳은 문제가 있었다.

1. **연구 방법 규율이 `research-status.md` §7-1에 얹혀 있었다.** status는 **덮어쓰는** 문서, 규율은 **쌓는** 문서라 수명이 다르다. status를 크게 갈아엎을 때 규율이 함께 휩쓸릴 구조였다.
2. **발표 규율 2종이 `논문 발표/` 폴더에 있었고 그 폴더는 git 추적이 되지 않는다.** 쌓는 문서를 복구 불가능한 곳에 두고 있었다.

### 무엇을 했나

`wiki/system/`에 `rules-` 접두어로 3개를 나란히 세웠다. 위키는 페이지 종류가 코드에 고정이라 새 하위 폴더를 만들면 인덱스에서 빠지므로, 폴더 대신 파일명 접두어로 묶었다.

| 파일 | 축 | 출처 | 용도 |
| --- | --- | --- | --- |
| `rules-research.md` | 연구 방법 | `research-status.md` §7-1 이관 | 방향 논의 세션이 논의 시 준수 + 사용자 연구 참조 |
| `rules-deck.md` | 발표 자료 구성 | `논문 발표/PPT_초안_규칙.md` 이관 + 보고서 구조 규율 발췌 편입(§2-1) | 스킬 실행 규칙 + 사용자 자료 검토 |
| `rules-talk.md` | 발표 방법 | `논문 발표/발표_팁.md` 이관 | **사용자가 발표 전 직접 열람.** 세션은 쌓기만 함 |

`research-status.md` §7-1은 포인터 한 문단으로 축소했고, §0 참조표에 3줄을 넣었다.

### 스킬 경로 정리

`seminar-deck-draft` 스킬은 `references/rules.md`를 정본으로 읽는다(스킬이 위키를 못 찾는 상황에서도 살아야 하므로 사본 유지). `PPT_초안_규칙.md`를 가리키던 4곳(SKILL.md ×2, build-recipe.md, 헬퍼 py ×2)을 새 경로로 고쳤다. 동기화는 frontmatter를 벗겨 복사하는 awk 한 줄이며 `CLAUDE.md`에 의무로 명시했다.

### CLAUDE.md 라우팅 규칙

"연구 방법을 물으면 research, 자료를 만들면 deck, 자리에서의 행동은 talk(세션은 읽지 않음)" — 새 조언이 들어오면 축을 먼저 가르고, 셋에 걸치면 쪼개서 각각 넣는다는 규칙을 새 절로 추가했다.
