## 2. 덱 구조

### 2-1. 서사가 먼저다

가장 상위 지적이었다. 슬라이드를 나열하기 전에 **한 줄짜리 주장과 그 주장에 도달하는 흐름을 먼저 정하고**, 각 슬라이드가 그 흐름의 어느 칸인지 대응시킨다. 흐름이 없는 덱은 초안으로도 제출하지 않는다.

초안 작업 시작 시 다음을 먼저 적어 사용자에게 보인다.

```
주장 한 줄:
흐름: (1) ... → (2) ... → (3) ... → (4) ...
슬라이드 대응: 1=표지, 2=목차, 3~4=(1), 5~7=(2), ...
```

### 2-2. 기본 골격

1. 표지
2. 목차 (장 이름만, 20pt, 군더더기 없이). **글머리 기호가 아니라 1, 2, 3 번호를 매긴다 (2026-08-10 확정).** 번호 크기는 본문과 같게 맞춘다
3. 본문 (각 장의 첫 슬라이드부터 제목에 **장 이름을 반복 표기**한다. 템플릿이 그렇게 되어 있다)
4. 결론
5. Q&A (40pt, 마지막 슬라이드)

### 2-3. 장 구성 규칙

- **문제 정의는 내가 해결할 부분만 남긴다.** 해결 대상이 아닌 갈래는 버리거나 한 줄로만 언급한다.
- **"우려하는 점" 같은 장을 만들지 않는다.** 마지막은 결론이며, 결론은 `결과 + 앞으로 할 일` 두 가지로만 구성한다.
- **실험 요약 장을 만들지 않는다.** 실험은 결과 장에서 지표와 함께 보인다.
- **제안 기법 장은 overview 구조도로 시작한다.** 개입 구조를 먼저 한 장으로 보이고, 세부는 그 뒤에 배치한다.
- Related work는 **묶는 기준을 실제 논문들에서 찾아 정한 뒤** 그 기준으로 묶는다. 임의로 묶지 않는다.
- **연관이 깊은 것만 남긴다.** 넓게 훑는 related work는 만들지 않는다.
- **prior 설명은 related work가 아니라 preliminary에 둔다.** 자세히 쓰지 않는다.

### 2-4. 분량 배분

- 결론은 섹션당 한두 줄로 짧게.
- 반대로 **분석이 필요한 부분은 길게 쓴다.** 짧게 할 곳과 길게 할 곳을 구분하는 것이 규칙이며, 전체를 균일하게 짧게 만드는 것이 아니다.
- **설명이 필요 없는 당연한 내용을 글로 쓰지 않는다.** 근거란에 자명한 문장을 채우지 않는다.

### 2-5. 서술 범위

**MILo에 국한된 문제로 보이게 쓰지 않는다.** 실험은 MILo 하나로 하더라도, 문제는 GS 기반 표면 재구성 전반의 공통 문제로 서술한다. nerfacto와 openmvs도 같은 구역에서 열화한다는 측정 결과를 앞쪽에 배치하면 실험을 늘리지 않고 이 요구를 충족한다.

## 2-1. 주간보고·정기보고 구조 (2026-07-25 피드백, 상시 적용)

랩세미나 덱이 아니라 **지도교수 정기 보고**일 때의 구조. 세미나 덱에도 오프닝 원칙은 그대로 쓴다.

- **두괄식**: "원래 하려던 것 → 현재 입장(이번 주 달라진 점) → 상세(실험·문헌)는 후술"
- 시작은 연구 목표의 **한 문장 요약**. 그 위에 이번 주 변화 2줄
- **문헌은 "정독했다"가 뉴스가 아니다.** "이 가설을 논문을 읽으며 강화했다"로 소비한다 — 선행의 한계 1줄씩 → "그래서 우리는 이렇게 한다". **논문 정독 자체를 요약 메인으로 내걸지 않는다**
- 실험은 "가설을 뒷받침하는 증거" 위치에 배치한다. 실험 목록 나열이 아니다
- **방어 논리는 간결하게만.** 예상 반박에 여러 장을 쓰면 그 자체가 약점 신호로 읽힌다
- 마무리는 "남은 것"

### 3-1-2. 구조도 색 분류와 배치 (2026-08-18 확정)

구조도의 요소를 **세 종류로 나누고 색을 다르게** 한다. 지금처럼 전부 같은 색이면 무엇이 데이터이고 무엇이 연산인지 읽히지 않는다.

| 종류 | 예 | 표시 |
| --- | --- | --- |
| **중간 산출물** | point cloud, confidence map, 3D Gaussians, mesh | 색 A |
| **프로세스** | SfM, render, densification, mesh extraction | 색 B |
| **loss** | photometric loss, mesh regularization | **색 C. 별도 표기** |

- **loss는 반드시 다른 색으로 구분**한다. 산출물이나 프로세스와 섞지 않는다
- **최종 output은 오른쪽 끝**에 둔다. 흐름이 왼쪽에서 오른쪽으로 읽히게 한다
- 세 색은 팔레트(1-1절) 안에서 고르고 **빨강은 쓰지 않는다**
- 범례를 그림 안이나 바로 아래에 단다

**overview 슬라이드 추가 요구**: Observation Confidence Map 상자 안에 **무엇이 들어 있는지**와 **어디로 이어지는지**를 한 줄씩 적는다. 지금은 이름만 있어 내용이 안 보인다.

### 3-1-3. 구조도 정밀 규칙과 색의 원칙 (2026-08-20 확정)

**구조도**
- **화살표는 무엇이 어디로 어떻게 들어가는지 명확해야 한다.** 대충 그은 선을 두지 않는다. 갈래가 있으면 갈래를, 합류가 있으면 합류를 그린다
- **아무 일도 하지 않는 네모는 지운다.** 그림에 있는 모든 상자는 입력을 받아 무언가를 내놓아야 한다
- **화살표의 굵기와 점선에는 이유가 있어야 한다.** 굵으면 왜 굵은지(주 경로·큰 데이터량 등), 점선이면 왜 점선인지(선택적·미구현·간접 등)가 범례나 캡션에 있어야 한다

**색의 원칙**
- **의미 없이 색을 쓰지 않는다.** 색은 정보를 나르는 채널이지 장식이 아니다
- **무채색 베이스 + 유채색 소량.** 안 중요한 것은 회색으로 깔고 중요한 것에만 색을 준다. 전부 색을 쓰면 아무것도 강조되지 않는다
- 색 배정에 일관된 규칙을 세우고 덱 전체에서 유지한다 (예: 데이터 대 프로세스, 남의 것 대 우리 것)
- 색이 갖는 통념적 인상도 고려한다 (예: 보라 계열의 정제된 인상)

**figure 출처**
- **남의 그림과 내 그림을 구분해 표시한다.** 인용 그림은 출처를, 자체 산출은 자체 산출임을 알아볼 수 있게

**상수 표기**
- **논문·발표의 "상수"는 근거 없이 쓰지 않는다.** `1, 2, …, n−1, n`은 괜찮으나 대놓고 `4`는 근거가 필요하다
- **구현이 4단계여도 원리상 n단계가 될 수 있으면 그림에는 `0, 1, …, n−1`로 그린다.** 구현 상수를 설계 상수처럼 보이게 하지 않는다

**시선을 끄는 장치**
- 개념을 한 장으로 설명하는 상징적 도해(프리즘 분광 같은)는 설득에 실제로 값을 한다. 다만 위 색·화살표 원칙을 지키는 선에서

### 3-1-1. 도식 규칙 (2026-08-10 확정)

- **입력과 출력을 글자로 명시한다.** 상자만 늘어놓지 말고 `Input` / `Output` 라벨을 붙인다. 출력이 여러 개면 전부 적고, 그중 무엇을 쓰고 무엇을 쓰지 않는지는 본문에서 갈라 쓴다.
- **기존 파이프라인은 회색, 이 연구가 추가하거나 바꾸는 부분만 강조색으로 칠한다.** 한 그림 안에서 무엇이 남의 것이고 무엇이 내 것인지 색으로 구분되어야 한다.
- **베이스라인 파이프라인을 임의로 줄이지 않는다.** loss와 GT 비교처럼 그 기법을 아는 사람이 당연히 찾을 요소를 빼면 그림이 발표자만 읽을 수 있게 된다.
- 개입 지점에 번호를 붙이고, 본문 항목이 같은 번호를 쓴다.

### 3-2. 결과 이미지

설명문을 옆에 붙이지 않는다. 라벨만 붙인다.

```
MILo   |   MILo + Uniform Prior   |   MILo + Ours
```

### 3-3. 그림 안 텍스트

- 라벨 14pt 굵게, 부가 설명 10.5 ~ 11pt
- 빨간색을 쓰지 않는다. 강조는 굵게와 크기로 한다
- 그림 자체의 색상 지도(히트맵 등)에는 색 제한을 적용하지 않는다. 금지 대상은 글자 색이다

## 4. 용어와 문체

### 4-1. 확정 용어

전문은 `terminology-preferences` 메모리를 따른다. 발표자료에서 특히 중요한 것만 적는다.

| 쓸 것 | 쓰지 말 것 |
| --- | --- |
| under-constrained | 저관측 |
| artifacts, floaters, holes | 붕괴 |
| photometric ambiguity | cheating (MILo 인용 시에만 따옴표로) |
| 외벽 | 파사드 |
| prior | (그대로 유지. 표준 용어다) |
| **복원** | **쓰지 않는다. `재구성`(reconstruction)으로 통일** (08-18 피드백) |
| 1, 2, 3 | "축" |
| 판별값, 지표, confidence | **신호** |
| 동일 기준 비교, 정량 대조 | **채점** |
| 데이터셋, 씬 | **무대** |
| 정규화 총량, 같은 양 | **예산** |

- **"under-constrained 영역"을 연구의 정의처럼 쓰지 않는다.** 정의는 "observed yet under-constrained"이며, 원거리 영역은 그 대표 사례다.
- **"mesh 결손"이라고 쓰지 않는다.** 실제 측정이 점 사이 거리 비교라면 mesh의 결손이 아니다. 측정한 것과 일치하는 표현을 쓴다. 예: "GT 점 대비 미복원 비율".

### 4-1-1. 제목 규칙 (2026-08-20 확정)

- **간결하게, 강조할 내용으로.** 길면 무엇이 main인지 파악되지 않는다
- **`with`과 `via`를 동시에 쓰지 않는다.** 어색하다
- **모두가 당연히 써야 하는 기법은 제목에서 뺀다.** 당연한 것을 제목에 넣으면 기여가 흐려진다. ours는 `ours without A` 대비로 보이면 충분하다
  - 본 연구 적용: prior가 당연한 구성이면 제목에 넣지 않는다. 남을 것은 방법의 고유 축이다

### 4-2. 문체

- **서술체는 `~함` 또는 명사형 끝맺음으로 통일한다 (2026-08-10 확정).** `~하였다`, `~했다`, `~한다`를 쓰지 않는다. 한 문서 안에서 섞지 않는다.
- 은유를 쓰지 않는다. 완결형 담백체.
- 회색 작은 글씨를 쓰지 않는다.

### 4-2-1. 대시 금지와 글머리 계층 (2026-08-10 확정)

**머리말 뒤에 대시를 붙여 설명을 잇는 형태를 쓰지 않는다.** 머리말을 상위 글머리로 두고, 설명은 한 단계 들여 쓴 하위 글머리로 붙인다.

쓰지 말 것

```
• 재료 — SfM이 이미 내놓는 카메라 포즈. 추가 촬영도 추가 학습도 없음
• 계산 — 공간을 voxel로 나누고 칸마다 각 범위를 저장
```

쓸 것

```
• 재료
    • SfM이 이미 내놓는 카메라 포즈. 추가 촬영도 추가 학습도 없음
• 계산
    • 공간을 voxel로 나누고 칸마다 각 범위를 저장
```

- 문장 안에서도 대시로 덧붙이지 않는다. 마침표로 끊거나 괄호를 쓴다.

### 4-2-2. 소제목은 명사구로 (2026-08-10 확정)

**상위 글머리(소제목)를 의문문으로 쓰지 않는다.** 짧은 명사구로 쓴다.

| 쓰지 말 것 | 쓸 것 |
| --- | --- |
| 무엇을 조절하나 | 조절 대상 |
| 왜 외부 모델을 쓰지 않나 | 외부 모델 미사용 이유 |
| 어디서 판정하나 | 판정 위치 |
| 무엇을 기준으로 나누나 | 판정 기준 |
| 어떻게 다르게 하나 | 조작 |
| 무엇으로 자리를 고르나 | 선택 기준 |
| 왜 짚는가 | (그 절의 내용을 가리키는 명사구) |
| 무엇을 표시하나 | 표시하는 자리 |
| 무엇을 다르게 주나 | 다르게 주는 것 |
| 왜 학습 전인가 | 학습 전에 하는 이유 |
| 오늘 어디까지 왔나 | 현재 진행 |
| 왜 좁은 쪽인가 | 좁은 쪽을 쓰는 이유 |

**판정 규칙 (2026-08-18 추가).** 위 표를 외우지 말고 **어미로 기계 판정한다.**
소제목이 아래로 끝나면 전부 위반이다.

`~하나` · `~주나` · `~쓰나` · `~뽑나` · `~맞추나` · `~있나` · `~없나` · `~되나`
· `~인가` · `~는가` · `~왔나` · `~골랐나` · `~할까` · `~일까`

또한 **`무엇을`, `어떻게`, `왜`, `어디서`, `어느`로 시작하는 소제목은 쓰지 않는다.**
의문사로 시작하면 어미가 무엇이든 의문문이다. 변환은 기계적이다 —
의문사를 지우고 남은 서술을 명사로 닫는다 (`왜 X인가` → `X 이유`,
`무엇을 Y하나` → `Y 대상`, `어디서 Z하나` → `Z 위치`).

**빌드 뒤 전수 검색한다.** 위 어미와 의문사를 정규식으로 훑어 0건인지 확인하고,
0건이 아니면 슬라이드를 넘기지 않는다.

### 4-2-3-0. 자료 전체를 영어로 (2026-08-18 확정)

**슬라이드 본문까지 영어로 작성한다.** 08-10의 "기술 용어만 영어" 규칙을 확대한 것이다. 국제 논문 조준이 목표이고 발표 자료가 그대로 논문 그림·문장의 초안이 되기 때문이다.

- 본문·캡션·표 머리글·축 라벨 전부 영어
- 구두 발표는 한국어로 하되 슬라이드는 영어
- 전환 중이라 한국어와 영어가 섞이면 **슬라이드 단위로 통일**한다. 한 슬라이드 안에서 섞지 않는다

### 4-2-3. 용어는 영어로 통일 (2026-08-10 확정)

기술 용어는 한글로 번역하지 않고 분야 표기 그대로 쓴다. 슬라이드 전체에서 같은 표기를 유지한다.

`Camera pose` · `Camera intrinsics` · `Sparse point cloud` · `Track length` · `Reprojection error` · `Pre-trained model` · `Per-pixel depth` · `Surface normal` · `Prior` · `Under-constrained region` · `Photometric loss` · `Densification (clone · split)` · `Geometric regularization`

- 모델 이름은 줄이지 않는다. `DA2`, `DA3`가 아니라 `Depth Anything V2`, `Depth Anything 3`.
- 장 이름도 영어로 통일한다: `Motivation` · `Terminology` · `Preliminary` · `Problem Definition` · `Related Work` · `Methods` · `Evaluation` · `Conclusion`. 목차와 슬라이드 제목이 같은 이름을 쓴다.
- 그림 라벨과 캡션도 같다. `복원 mesh — 배경 구조물`이 아니라 `복원 mesh (배경 구조물)`로 쓴다.
- **슬라이드 제목에도 예외를 두지 않는다 (2026-08-18 확정).** 장 이름과 소제목은 세로선으로 잇는다: `Terminology | SfM` · `Evaluation | 정량 결과`. em 대시(`—`)는 제목·본문·라벨·캡션 어디에도 쓰지 않는다. 사유는 대시 연결이 AI 생성물의 인상을 준다는 사용자 지적.
- 하위 글머리로 내리면 세로 공간을 더 쓰므로, 그림 높이와 본문 시작 위치를 다시 계산한다.


### 4-2-4. 자기 방어 문구 금지 (2026-08-18 확정)

**결과를 어떻게 읽으라고 청중에게 지시하는 문장을 슬라이드에 넣지 않는다.**

- 쓰지 않는다: `개선을 주장하는 자리가 아님`, `개선으로 읽지 않음`, `단일 런 · 통계 검정 전`
- 이유: 방어가 필요한 자리는 결론 슬라이드 한 곳이면 충분하고, 표마다 반복하면 발표자가 결과를
  변명하는 인상을 준다. 수치의 성격은 슬라이드 제목과 표 구성으로 이미 드러난다.
- 질문이 들어오면 구두로 답한다. 슬라이드에 미리 적어 두지 않는다.

### 4-3. 강조

- **굵게와 크기 차등만 사용한다.**
- **빨간색 글자를 쓰지 않는다.** 오류 표시 전용이다.
- 표 안에서 파란색은 허용한다.

### 4-4. 주장 강도

**"학습 전"을 "학습 없이"로 번역하지 않는다.** 이 방법은 baseline을 그대로 전부 학습시키고 감독의 배분만 바꾼다. 학습을 부정하는 인상을 주는 문장을 쓰지 않는다.

**학습 전에 아는 것은 기하가 아니라 감독의 신뢰도다.** 그래서 값이 정확할 필요가 없고 순위만 맞으면 된다. 실측도 상대 비율로만 주장하고 있으므로 문장도 그 수준에 맞춘다.

| 쓸 것 | 쓰지 말 것 |
| --- | --- |
| 학습 전에 알 수 있는 정보로 감독을 배분한다 | 학습 없이 판단한다 |
| 어디의 감독이 믿을 만하지 않은지를 미리 안다 | 어디가 잘못될지를 미리 안다 |
| 상대 순위를 맞힌다 | 품질을 예측한다 |
| 최적화가 바꿀 수 없는 촬영 기하에서 온다 | 모델을 보지 않아도 된다 |

### 4-5. 자기모순 점검

발표 전 전체를 통독하며 서로 어긋나는 주장을 찾는다. 실제 지적된 예는 다음과 같다.

> "거리가 아니라 관측 각도 때문이다"라고 주장해놓고, 다른 장에서 "거리가 멀수록 무너지는 것은 당연하다"라고 말하는 것.

거리 효과를 인정하는 문장과 각도 효과를 주장하는 문장이 같은 덱에 있으면, **거리를 통제한 뒤에도 각도 효과가 남는다**는 형태로 통일한다.

## 5. 지표와 결과 제시

### 5-1. 순서

1. **관례 지표를 먼저 보인다.** Chamfer distance, F1-score.
2. 그 지표가 무엇을 못 재는지 보인다.
3. **그 다음에 자체 지표를 도입한다.**

자체 지표를 먼저 꺼내지 않는다.

### 5-2. 정의 우선

**지표를 쓰기 전에 그 지표를 먼저 설명한다.** 설명하지 않은 지표로 평가한 결과를 보이지 않는다.

### 5-3. mesh 자체 품질 지표

표면 자체를 평가하는 지표도 존재한다. mesh 내각, 변의 최소 및 최대 길이 등. 해당하는 주장을 할 때 검토한다.

### 5-4. 인과와 상관

결과를 분석할 때 인과 관계와 상관 관계를 명확히 구분해 서술한다. 상관을 관찰한 것이면 상관이라고 쓴다.

### 5-8. 결과는 수치가 아니라 의미를 쓴다 (2026-08-20 확정)

- **"결과가 이렇게 나왔습니다"와 표를 그대로 읽는 서술을 쓰지 않는다.** 슬라이드에 적을 것은 **그 값이 갖는 의미, 그에 대한 해석, 그리고 가설이 어떻게 증명되었는가**다
- 예: `0.1739`를 적는 것으로 끝내지 않고 — 이 값이 무엇을 뜻하는지, 왜 그렇게 나왔다고 보는지, 어떤 가설이 이것으로 지지되거나 반증되는지

### 5-9. 비교의 배치와 표현 (2026-08-20 확정)

- **같은 계열끼리 비교한다.** 성격이 다른 계열을 한 줄에 놓고 우열을 말하지 않는다
- **차이가 작으면 퍼센트로 표기한다.** `0.001 대 0.0015`는 절대 차이로는 안 보이지만 **50% 차이**로 쓰면 보인다
- **비교하고 싶은 대상을 나란히 둔다.** 지표 행·열 순서를 그 기준으로 정한다
- **비교 이미지는 차이가 극단적으로 드러나는 위치를 잡거나, 그 분야가 자주 쓰는 비교 방식을 따른다**

### 5-6. 비교 그림에는 GT를 함께 둔다 (2026-08-18 확정)

정성 비교를 낼 때 **GT를 한 열로 박아 둔다.** 방법들끼리만 나열하면 무엇이 옳은지 판단할 기준이 없다. GT가 없는 영역이면 그 사실을 캡션에 적는다.

### 5-7. 수식 표기 (2026-08-18 확정)

- **수식은 본문 크기로 띄우지 말고 아래첨자·작은 크기로** 배치한다. 슬라이드의 주인공은 그림과 결론 문장이지 수식이 아니다
- **"우리가 개입할 자리"처럼 방법의 위치를 가리키는 표시도 아래첨자 크기**로 단다. 본문과 같은 크기로 쓰면 설명이 두 줄기로 갈린다

### 5-5. 숫자 규칙

- **확정된 수치만 쓴다.** 출처는 `UnderConstrained-GS-Recon\EXPERIMENT.md`다.
- **절대값을 타 논문 수치와 비교하지 않는다.** 같은 지표 안에서의 상대 비교만 한다.
- 개입(H3) 개선 수치는 **존재하지 않는다.** 미래형으로만 쓴다.
- 예비 결과를 실을 때는 `단일 실행 · 통계 검정 전 · 대조군 비교 전` 단서를 반드시 병기한다.
- 한 장에 숫자를 너무 많이 싣지 않는다. 핵심 장은 두 개 이내가 적절하다.

## 6. 초안 제출 전 점검표

초안을 사용자에게 넘기기 전에 전부 확인하고, 결과를 함께 보고한다.

**구조**

- [ ] 주장 한 줄과 흐름이 문서 앞에 적혀 있다
- [ ] 각 슬라이드가 흐름의 어느 칸인지 대응된다
- [ ] 마지막에서 두 번째가 결론(결과 + 할 일), 마지막이 Q&A다
- [ ] "우려하는 점", "실험 요약" 장이 없다
- [ ] 제안 기법 장이 overview 구조도로 시작한다

**형식**

- [ ] 모든 본문 슬라이드가 slideLayout2 계열을 쓰고 개체 틀에 내용이 들어 있다
- [ ] 모든 본문 슬라이드에 푸터와 쪽번호가 있다
- [ ] 좌우 여백 0.71인치를 지켰다
- [ ] 본문 영역(폭 11.62인치) 밖으로 나간 도형이 없다
- [ ] 글꼴이 Pretendard 계열이다
- [ ] 목차가 글머리 기호가 아니라 번호로 되어 있다
- [ ] 표에서 템플릿 기본 서식(청록 머리 · 파란 줄무늬)을 껐고 톤 다운 팔레트로 덮었다
- [ ] 도형과 강조색이 1-1 실사용 팔레트 값이다

**그림**

- [ ] 글만 있는 슬라이드가 없다
- [ ] MILo 구조도 위에 제안을 겹친 그림이 있고, 영향 경로가 화살표로 끝까지 그려져 있다
- [ ] 결과 이미지에 설명문 대신 라벨이 붙어 있다

**08-18 피드백 반영분**
- [ ] "복원"을 쓰지 않고 "재구성"으로 통일했다 (4-1)
- [ ] 슬라이드 본문이 영어다 (4-2-3-0). 섞였다면 슬라이드 단위로 통일했다
- [ ] 페이지 번호가 오른쪽 위에 있다 (1-4-1)

- [ ] 최종 output이 오른쪽 끝에 있다 (3-1-2)
- [ ] overview의 Observation Confidence Map에 내용과 연결이 한 줄씩 적혀 있다 (3-1-2)
- [ ] 정성 비교에 GT 열이 있다 (5-6)
- [ ] 수식과 "개입할 자리" 표시가 아래첨자 크기다 (5-7)

**08-20 피드백 반영분**
- [ ] 구조도의 모든 화살표가 무엇이 어디로 들어가는지 명확하다 (3-1-3)
- [ ] 아무 일도 안 하는 상자가 없다 (3-1-3)
- [ ] 색이 정보를 나른다 — 무채색 베이스에 유채색 소량, 배정 규칙이 덱 전체에서 일관 (3-1-3)
- [ ] 화살표 굵기·점선에 이유가 있고 범례나 캡션에 적혀 있다 (3-1-3)

- [ ] 결과 슬라이드가 수치 나열이 아니라 의미·해석·가설 검증을 쓴다 (5-8)

- [ ] 자기 방어 문구(`개선을 주장하는 자리가 아님`, `단일 런 · 통계 검정 전`)가 없다
- [ ] 소제목이 의문문이 아니라 명사구다. **4-2-2의 어미·의문사 목록으로 전수 검색해 0건**임을 확인했다 (눈으로 훑지 말 것)

- [ ] 도식에 Input / Output이 명시되어 있고, 기존 파이프라인은 회색, 제안 부분만 강조색이다
- [ ] 빨간색 글자가 없다
- [ ] 자기모순 통독을 했고 발견 사항을 보고했다

**지표**

- [ ] 쓰인 모든 지표가 먼저 정의되어 있다
- [ ] 관례 지표가 자체 지표보다 앞에 있다
- [ ] 확정 수치만 쓰였고 출처를 확인했다
- [ ] 인과와 상관이 구분되어 서술되었다

- [ ] 계산상 여유가 10퍼센트 미만인 상자를 목록으로 보고했다

## 7. 미결 항목 표기

초안 작성 중 사용자 판단이 필요한 부분은 **추측으로 채우지 않는다.** 다음 형식으로 표시하고, 별도 목록으로 함께 제출한다.

슬라이드 안 표기:

```
[[확인필요: 무엇을 정해야 하는지]]
```

제출 시 함께 내는 목록:

```
## 확인 필요 목록
- s7 : 어떤 수치를 쓸지 (후보 A, B)
- s12: 그림 재제작 필요 (기존 그림이 요구를 못 맞춤)
```

제출 전 `[[확인필요` 를 전수 검색해 목록과 개수가 일치하는지 확인한다.
