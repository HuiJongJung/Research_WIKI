# 260820 연구 전반 피드백

> 받은 내용을 보존하는 동결 기록. 대응은 progress-2026-08-20과 open-items에서.

## 받은 지적

1. **접근이 naive하고 scope가 넓다** — "SOTA로 hole 있는 object 복원이 잘 안 되더라 → 어떻게 해결하지"라는 문제 정의 자체가 그렇다.
2. **왜 생기는지의 원론적 이유를 찾지 못하고 추측만 한다** — 본인 추측 예: photometric상 hole이 까맣게 보이는데 그것이 진짜 hole인지 까만 표면인지 구분하지 못해 완전한 구멍을 뚫지 못하는 것 아닌가.
3. **GS mesh recon의 survey와 큰 문제의 계보를 먼저 따라가며** 지식을 쌓고 시각을 넓히는 것이 중요하다.
4. **명확하고 과하게 넓지 않은 문제를 잡고, 기존 기법들의 아이디어를 적당히 조합해 그것이 잘 된다는 증명**을 하는 편이 좋다.

5. **문제의 pioneer와 계보를 따라가라** — 단편적으로 "SOTA 해보니 안 되네, 고쳐야지"가 아니라, 그 문제에 pioneer가 있다면 그것을 바탕으로 문제를 깊이 이해하고 **근본 원인을 해결하려 해온 계보를 따라가며** 자기 접근법을 찾는 것이 맞다.

## 추가 피드백 (같은 날, 3축 분류)

### 연구 방법 (A축)

6. **가설을 세웠으면 그 가설이 성립한다는 것 자체를 증명해야 한다** — 뇌파로 mesh를 복원한다면 그 신호가 그런 정보를 담는다는 증명이 선행되어야 하듯이.
7. **70~80% 겹치는 논문이 있어도 쓸 수 있다.** 남는 20~30%가 가능성이다. 같은 classification도 covariance에 따라 달라진다. **연구자는 "이거랑 비슷하네"라며 clustering하는 사람이 아니라 비슷하더라도 차이를 찾아내는 사람이다.** 똑같은 것이 나왔다고 던지고 포기하지 말고 차별점을 찾아라. 완전히 새로운 것은 만들 수 없다.
8. **A계열(고성능)을 못 이기고 B계열만 이긴다면, B계열이 왜 좋은지를 서론부터 강조해야 반박을 막는다** (예: 성능은 낮지만 추가 메모리 없이 학습됨). **빌드업이 중요하다** — 제목부터 서론·본문·결론까지 하나를 끝까지 가져간다.
9. **벤치마크가 없는 것은 못 만든 게 아니라 필요 없어서일 수도 있다.** 돈(메모리를 더 사는 등)으로 해결되지 않는 문제를 잡는 것이 좋다. 단 "메모리는 적게 쓰지만 성능이 많이 낮다"는 약하다.

### 발표 자료·결과 제시 (B·C·E축)

10. 구조도: 화살표는 무엇이 어디로 어떻게 들어가는지 명확히 / 아무 일도 안 하는 네모는 삭제 / 데이터와 프로세스 색 구분 / **색에 원칙** (안 중요한 것은 회색, 무채색 베이스에 유채색을 적당히 — 의미 없이 색 쓰지 말 것) / 굵기·점선에도 이유 / figure는 남의 것과 내 것 구분 / PRISM 그림 같은 장치도 마음을 사로잡는다.
11. **논문의 "상수"는 근거 없이 쓰지 않는다.** 1·2·…·n−1·n은 되지만 대놓고 "4"는 근거 필요. 구현이 4단계여도 n단계가 될 수 있으면 그림에는 0·1·…·n−1로.
12. 결과 제시: **"결과가 이렇게 나왔어요"와 표 설명 나열 금지** — 값의 의미·해석·가설이 어떻게 증명됐는지를 쓴다 / 같은 계열끼리 비교 / 차이가 작으면 퍼센트로(0.001 대 0.0015 = 50%) / 비교 대상을 나란히 배치 / 비교 이미지는 차이가 극단적인 위치나 분야 관행대로.
13. 제목: with과 via 동시 사용은 어색 / 길면 main이 안 보임 / 간결하게 강조할 내용으로 / **모두가 당연히 쓰는 기법은 제목에서 뺀다** (ours는 "ours without A" 대비로 보이면 됨).

### 발표 태도 (D축)

14. 세미나에서 피드백을 들으면 **즉각 "그럼 이것도 같은 문제네요"라며 그 자리에서 정정하는 반응이 좋다.**

## 위키 세션 1차 검토 (같은 날)

- 지적 1은 정당 — 단 발표된 버전이 내부 정리(깊이 비 변인·중간 지대·완결 구역)보다 낡았던 전달 문제도 겹침. 본인이 내부 정리를 아직 자기 언어로 소화하지 못한 상태.
- 지적 2의 본인 추측은 실패 해부도 6력 중 2번(뚜껑 최소값)과 동일 — 직관이 틀린 게 아니라 여섯 중 하나임을 몰랐던 것. **진짜 공백은 6력의 실측 검증 부재** → 해부도 실측 4건을 최우선으로 상향.
- 지적 4에 맞는 좁은 문제 후보 = **중간 지대(회복 가능 전선)**: "얕은 개구는 회복 가능한데도(AmbiSuR 존재 증명) base가 메운다 — 학습 전 촬영 기하로 지목해 살린다." 기존 아이디어 조합(PGSR 게이트를 학습 전으로 + CDGS류 가중을 기하로 + clone 억제)이며 성공 기준 판정 가능. **채택 여부는 사용자 결정 대기.**
- 지적 3의 실행형 = 계보 지도 조립(Q-28) + 그 위에서 1군 읽기.

- 지적 5는 앞선 셋보다 한 겹 깊다. **우리가 보던 계보(GS mesh recon)는 무대의 계보이지 문제의 계보가 아니다.** 우리 문제("관측이 결정하지 못하는 영역을 어떻게 다룰 것인가")의 계보는 space carving/photo hull → MVS 가시성 추론 → 불확실도 인지 재구성 → next-best-view/reconstructability → shape completion으로 이어지며 GS보다 오래됐다. 이 계보에서 우리 자리는 **"카메라를 더 놓을 수 없고 채우기도 원하지 않을 때"**의 빈칸이다. Smith 2018 읽기와 visual hull 앵커(Q-27)를 이미 밟고 있었으나 **"우리 계보"라는 자각 없이 흩어져 있었다.** Q-28을 무대의 계보(a)와 문제의 계보(b)로 분리하고 b를 우선한다.

- 추가 피드백 중 **우리에게 특히 무겁게 걸리는 것 셋**: ① 지적 8이 우리 구도와 동일 — AmbiSuR(A계열)를 못 이기고 MILo(B계열) 위에서 개선하므로 **"왜 MILo 계열인가"를 서론부터 밀어야 하는데 지금 그 문장이 없다** (in-loop mesh라 mesh가 학습에 참여, 배경까지 산출 등이 후보) ② 지적 13이 제목에 직결 — prior·densification은 수단이므로 제목에 남을 것은 "관측 기하로 감독을 배분한다" ③ 지적 6은 이미 수행 중(H2·회복 전선 검증이 "confidence가 실패를 예측한다"의 증명)이나 **그것이 증명 대상임을 명시적으로 쓰지 않았다.**
