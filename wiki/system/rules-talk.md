# 규율 — 발표 자리에서의 행동

> **3축 규율 중 「발표 방법」.** `rules-deck.md`가 **자료**의 규칙이라면 이 문서는 **발표하는 자리에서의 행동**을 담는다.
> 연구 방법 규율은 `rules-research.md`.
>
> **용도**: 세션이 참조하는 문서가 아니다. **발표 전에 사용자가 직접 읽는 팁 모음**이며, 세션은 새 조언이 들어올 때 여기에 쌓기만 한다.

> **새 피드백을 반영할 때**: 기존 항과 같은 말이면 올리지 않고, **기존 내용을 포함하면서 더 나아간 것이면 기존 항을 지우고 대체한다**(추가가 아니라 교체). 충돌하면 임의로 고르지 않고 사용자에게 확인한다. 전문은 `rules-research.md` §0.
---

## 1. 피드백을 받을 때 (2026-08-20)

**즉각 정정이 반응이 좋다.** 지적을 받으면 받아 적고 넘어가는 것보다, **그 자리에서 "그럼 이것도 같은 문제네요"라며 중복되는 다른 지점을 스스로 짚고 정정하는 것**이 낫다.

- 지적 하나가 여러 슬라이드·여러 결정에 걸치는 경우가 대부분이다. 하나만 고치겠다고 하면 나머지를 못 본 것으로 읽힌다
- 준비: 발표 전에 **"이 지적이 오면 어디까지 번지는가"**를 미리 한 번 훑어두면 즉답이 가능하다
- 방어가 아니라 확장으로 답한다. "그건 이래서 그렇습니다"보다 "말씀대로면 저쪽도 같은 문제입니다"가 낫다

## 2. 결과를 말할 때 (2026-08-20)

**"결과가 이렇게 나왔습니다"로 시작하지 않는다.** 표를 읽어주는 것도 아니다.
말할 것은 **값의 의미 → 그에 대한 내 해석 → 가설이 어떻게 증명·반증되었는가** 순서다.

- 수치는 근거이지 내용이 아니다
- 차이가 작으면 퍼센트로 말한다 (0.001 대 0.0015 = 50% 차이)

## 3. 약한 자리를 먼저 말할 때 (2026-08-20)

**고성능 계열을 못 이기고 다른 계열 위에서 개선한 경우, 그 계열을 쓰는 이유를 서론부터 깔아야 한다.**

- 결과 슬라이드에서 처음 변명하면 늦는다. 제목 → 서론 → 본문 → 결론이 같은 이유를 계속 밀고 있어야 한다
- 예시 구도: "이런 환경에서는 자원이 부족하다 → 그래서 이 계열이 쓰인다 → 우리는 거기서 개선했다"
