# 박사님 세미나 피드백 — 정리 및 채울 양식 (2026-07-31)

## 0. 한 줄 판정

**재료가 없어서 지적받은 게 아니라, 재료가 10배 많은데 고르지 않아서 지적받았다.**

피드백 항목을 하나씩 대조해보면 "survey / baseline 선정 / ablation 설계 / 실험일지"는 이미 되어 있다. 안 되어 있는 건 **압축·그림·목표 무대(venue)** 세 가지뿐이다. 그러니 이 문서의 목적은 새로 만들기가 아니라 **버리기**다.

---

## 1. 피드백 항목 3분류

박사님 노트의 항목을 현재 상태와 대조한 것. (판정 근거는 연구 스냅샷 + `journal.md` + `wiki/sources/` — 틀린 칸 있으면 고칠 것)

### A. 이미 있음 — 새로 할 일 아님

| 피드백 항목 | 현재 상태 |
|---|---|
| survey를 잘 해서 | 위협 통합표 8+행, SOTA 3분류(A/B/C), 영역 분리 지도, 읽기 계획 6단계 |
| 어떤 논문과 어떻게 비교할지 | CoMe / AmbiSuR / G4Splat / CoMapGS / Expo-GS — 충돌 지점·방어 각각 확보 |
| baseline 선정 | MILo (4캠프 중 in-loop 유일 → 개입 표면적 최대, 선정 근거 문서화됨) |
| 정량/정성 비교 | 4조각 평가 설계 (Spires 메인 / 합성 인과 / GT 없는 씬 정성 / DTU·TnT 방어) |
| ablation을 어떻게 | E4 = global vs selective kill test, 사전 등록 수준으로 설계 완료 |
| 실험일지 쓰기 | EXPERIMENT.md + `design_log/` 이미 운영 중 |
| 내 연구의 동기 | 평가 공백 + photometric shortcut, 경쟁자 자인 인용까지 확보 |

**⇒ 7항목이 이미 되어 있다.** 피드백을 "아무것도 안 됐구나"로 읽으면 오독이다.

### B. 있는데 전달이 안 됨 — 압축 문제

| 피드백 항목 | 진짜 문제 |
|---|---|
| 내가 뭘 원하는지 명확하게 | 답은 있음. 근데 답이 여러 층(진단/개입/평가)이라 한 문장으로 안 나옴 |
| contribution이 명확하게 | novelty 원자 ⓐ~ⓓ + 공석 ⓐ~ⓔ = 9개. **9개는 contribution이 아니라 목록이다.** 3개로 잘라야 함 |
| 우선순위 / 주제 쪼개기 | 트랙 A/B로 쪼개져 있으나 발표에선 둘 다 같은 비중으로 나갔을 것 |
| 배경지식 없는 사람도 이해 | 현재 서사가 "CoMe의 Ĉ*=β/ℒ_rgb가…"에서 시작하면 아무도 못 따라옴 |
| 간결하게 중요한 내용만 | 위와 동일 원인 |

**⇒ 여기가 진짜 지적 지점.** 정리가 안 된 게 아니라 **정리된 게 너무 많아서 선택이 없었다.**

### C. 진짜 빈칸 — 새로 해야 함

1. **venue 결정** — 어디에 낼지, 그 수준이 요구하는 novelty 강도
2. **Fig.1 (진단 그림)** — 방법은 확보됨(field 삼선형 보간 → SH DC 덮어쓰기 → 렌더). 아직 안 뽑음
3. **파이프라인 flow 그림** — 없음
4. **발표 골격 (1장 압축)** — 없음

## 2. 압축 양식 — 각 칸 **한 문장**, 초과 금지

> 규칙: 재료는 이미 있다. 이 표의 목적은 생성이 아니라 **선택과 절단**이다.
> 각 칸에 두 문장 이상 쓰고 싶어지면, 그건 그 칸이 아직 안 정해졌다는 뜻이다.

| # | 칸 | 한 문장 | 재료 위치 |
|---|---|---|---|
| 1 | **문제** (배경지식 0인 사람에게) | | 평가 공백 + 주변부 열화 |
| 2 | **왜 아직 안 풀렸나** | | SOTA 3분류 C = "측정 수단 부재의 벽" |
| 3 | **내 핵심 주장** (1개만) | | "보인다 ≠ 결정된다" |
| 4 | **contribution** (최대 3개, 9개 아님) | ① <br> ② <br> ③ | novelty 원자 ⓐ~ⓓ / 공석 ⓐ~ⓔ 중 선별 |
| 5 | **input → output** | | SfM 부산물 → confidence field → 차등 supervision → mesh |
| 6 | **baseline & 비교 대상** (최대 3편) | | MILo(base) + ? + ? |
| 7 | **성공의 정의** (숫자로) | | "밴드별 Chamfer/F1에서 uniform 이김 + WELL 무회귀" |
| 8 | **ablation 한 줄** | | E4: A0 / A1 selective / A2 global, 예산 일치 |

### 채우기 주의

- **4번이 가장 어렵고 가장 중요하다.** 현재 novelty 후보가 9개인데, 리뷰어는 3개까지만 기억한다. 9개를 다 말하면 0개를 말한 것과 같다.
- **7번을 못 채우면 나머지가 다 무의미하다.** "얘네보다 잘 나와야 한다"의 '얘네'와 '잘'을 숫자로 못 쓰면 아직 target이 안 정해진 것.
- 못 채운 칸 = 다음 주 할 일. 억지로 채우지 말고 비워두고 표시할 것.

## 3. 진짜 빈칸 4개 — 각각의 착수 형태

### ① venue 결정

| 후보 | 마감 (확인 필요) | 요구 novelty 강도 | 우리 fit |
|---|---|---|---|
| CVPR / ICCV | | 높음 — 방법 novelty 요구 | |
| ECCV | | 높음 | 동시투고 리스크 있던 곳 |
| 3DV / WACV | | 중간 — 진단+평가 기여 수용 여지 | |
| TVCG / CGF 등 저널 | | 완결성·분량 요구 | 진단(H1·H2)만으로도 성립 가능? |

핵심 질문 한 줄: **"진단(H1+H2)만으로 낼 수 있는 무대가 있는가, 아니면 개입(H3) 결과가 반드시 필요한가?"**
→ 이 답에 따라 남은 일정이 통째로 갈린다. 조사해서 박사님께 보고할 항목으로 이미 지정됨.

### ② Fig.1 — 진단 그림

- 방법: 학습된 씬 로드 → Gaussian 위치에서 field 삼선형 보간 → `_features_dc` 덮어쓰기 + `_features_rest.zero_()` → 평소대로 렌더
- **MILo 코드 안 건드리고 사후 조회로 나옴** = 개입 실험 전에 확보 가능
- 4패널 목표: `Render | 내 field (a priori) | CoMe Ĉ (a posteriori) | GT 오차`
- 컬러맵 자유 (PPT 빨간 글씨 금지는 텍스트 한정, 그림엔 무관)

### ③ 파이프라인 flow 그림

```
[입력 이미지] → [COLMAP/SfM] → ┌─ 기존: 균일 supervision ──────┐
                                └─ 우리: 부산물 통계            │
                                    (각도·track·reproj)        │
                                        ↓                      │
                                 [Observation Confidence Field] │
                                        ↓                      ↓
                                 [차등 supervision] ──→ [MILo 학습] → [mesh]
                                                                    ↓
                                                          [밴드별 GT 평가]
```
위는 뼈대 초안. 여기서 **"이 그림의 어느 화살표가 내 기여인가"**를 색으로 표시할 수 있어야 함. 못 하면 기여가 아직 흐린 것.

### ④ 발표 골격

§2 표를 그대로 슬라이드 순서로 쓰면 됨:
문제(1) → 왜 안 풀렸나(2) → 주장(3) → **Fig.1** → 방법 flow(5) → contribution(4) → 실험 설계(6,7,8) → 현재 결과 → 다음

**이번 발표에서 뺄 것**: 위협 통합표 전체, 읽기 계획, 용어 논쟁, 경쟁자 수식 해부(CoMe Ĉ* 유도 등). 전부 방어용 자산이지 발표 본문이 아니다. **질문 나오면 그때 꺼내는 카드다.**

## 5. 읽기 — 범위형은 중단, 깊이형은 유효

읽기에 두 종류가 있고 성격이 정반대다.

- **범위형** (새 논문 수확) — 중단. 위협 통합표에 빈칸 없고, 17편+ 수확으로 경계는 이미 그어졌다.
- **깊이형** (이미 인용한 것을 방어 가능한 수준까지) — **유효하며, 압축의 전제조건이다.**

이유: **압축은 이해를 요구한다.** 이해된 항목은 한 문장으로 자를 수 있지만, 이해 안 된 항목은 자를 수가 없어서 통째로 옮겨 붙게 된다. 세미나에서 "다 넣은" 것이 아까워서가 아니라 **무엇을 빼도 안전한지 판단할 수 없어서**였다면, 그건 정리 스킬 문제가 아니라 소화 문제다.

박사님 노트의 세 항목이 정확히 이 진단 도구다 — "배경지식 없는 사람에게도 이해할 수 있게" / "GPT한테 설명해보고 내가 설명 잘 한 것 같냐 물어보기" / "내 주장이 타당한가?". **설명하지 못하는 부분 = 아직 알지 못하는 부분.**

### 방어 가능성 트리아지

| 등급 | 상태 | 처리 |
|---|---|---|
| **A** | 내가 유도·재현 가능. 파고들어도 방어됨 | 발표 본문 사용 가능 |
| **B** | 결론은 알지만 근거는 남의 말 | 인용까지만, 본문 금지 |
| **C** | 옮겨 적었으나 실제로는 모름 | 발표에서 제외 |

**규칙: B·C는 발표에 넣지 않는다.** 그러면 읽을 목록이 유한해진다 — "발표에 반드시 필요한데 C인 것"만 읽으면 되고, 나머지 C는 뒤로 민다.

### 이미 표시된 얇은 지점 (새로 찾을 필요 없음)

C·B 후보 — 스냅샷에 본인이 이미 조건을 달아둔 것들:

- Free360 — "abstract 수준만 확인, **인용 전 본문 확인**" (자가 표시)
- defocus 논문 (NN 2026) — "intro 작성 전 정독" 유예 중
- 읽기 계획 5단계 (FSGS·SparseGS·DNGaussian) / 6단계 (Reconstructability 2편·Mostegel) — **"훑기"로만 표시**
- 서랍 G (TurboGS·LeGS·GSFixer·Motive·LASER) — "개입 설계 시점"으로 유예

A 후보 — 정독 완료 + WIKI source 페이지 보유: CoMe / AmbiSuR / MILo / Expo-GS / CoMapGS / GOF.

**단 A 후보 안에서도 갈림선이 있다**: 남의 수식 유도(CoMe `Ĉ* = β/ℒ_rgb`)나 남의 ablation 숫자(AmbiSuR Table 4 F/G)를 발표 본문에 쓸 거라면, 기준은 **칠판에서 다시 유도할 수 있는가**다. 못 하면 B이고, B는 본문에 안 들어간다.

### 착수 형태

§2의 8칸을 채운 뒤, 각 칸의 근거에 A/B/C를 매긴다. **C가 붙은 칸이 곧 읽기 목록이고, 그 목록의 길이가 곧 유한한 다음 주 분량이다.**

## 부기 — 자기검열 주의 지점

피드백 15항목 중 7항목은 이미 되어 있다(§1-A). "정리를 더 해와라"를 **"새 논문을 더 읽어야 한다"**로 번역하면 방향이 반대로 간다 — 노트 어디에도 범위를 넓히라는 말은 없고, 전부 그리고·쓰고·코딩하라는 출력 요구였다. 단 §5의 깊이형 읽기는 예외이며, 그것도 발표에 필요한 만큼으로 한정된다.

"설득은 리뷰어를 설득하는 것"이라는 말은 **기준선을 자기 밖에 두라**는 뜻이다. 스스로 만족할 때까지 미루는 대신, 리뷰어가 통과시킬 최소선을 정하고 거기까지만 한다.
